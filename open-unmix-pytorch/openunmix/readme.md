## OpenUnmix base content

The original OpenUnmix pipeline, along with the other files necessary for proper execution:

- `model` definition of the core OpenUnmix separation model architecture.
- `data` dataset loaders and augmentation utilities for MUSDB18 (version "bis" reduces validation chunk sizes for limited memory).
- `filtering` multichannel Wiener filter implementation (`wiener`) and phase restoration utilities for spectrogram post-processing.
- `predict` high-level functional inference interface (`separate`) to execute source separation on audio tensors or files.
- `transforms` definition of STFT/ISTFT transforms and filterbank conversions.
- `utils` helper utilities for loading pretrained OpenUnmix models and parameters.

## Complex spectrogram approximation

### `spectrogram.py` 
Complex trainable spectrogram module. Crucially, the user must specify the `encoder` attribute, which acts as a reference for the output length along the time dimension.

The forward pass is straightforward: the audio input tensor $(B, C, N_0)$ is split across the channel dimension and passed to the MIMO SSM (`magssm.py`), producing a complex tensor.

To match the spectrogram format generated by the STFT in the OpenUnmix pipeline, the real and imaginary parts are concatenated across an additional dimension. The output tensor has shape $(B, C, F, T, 2)$ with dtype `torch.float`.


#### `magssm.py`
Wrapper for applying the complex MIMO SSM to a tensor of shape $(B, N_0)$, returning an output of shape $(B, \frac{T}{\text{subsampling factor}}, d_{\text{out}})$ after adding a dimension. Technically, this class could be removed entirely; however, it is retained in this version to avoid breaking compatibility with saved `.pth` checkpoint files.


## Decoding the C-MagSSM object with an SSM

### `decoder.py`

Trainable decoder aiming to reproduce the behavior of the ISTFT while remaining fully differentiable. Note that when invoked, the decoder requires a `length` parameter to produce a signal of the correct output shape. 

Example: 
```python
X = encoder(x.float())
y_hat = trainable_decoder(X, length=x.data.shape[-1])
```

In the forward pass, the input tensor of shape $(B, C, F, T, 2)$ is transformed into a complex-valued tensor of shape $(B, C, F, T)$, split across channels, and sent per channel to the `magssm_decoder` pipeline. The individual signals are then stacked to produce an output of shape $(B, C, N_0)$, matching the length $N_0$ of the original audio signal. 

Since complex-valued SSMs are used, the raw output is also complex-valued. To approximate the target real-valued audio signal, only the real part is returned.


#### `magssm_decoder_second_version.py`

More than a simple wrapper around a MIMO SSM: it encapsulates the logic of Hermitian symmetry on the complex spectrogram as well as the overlap-add (OLA) process performed by the ISTFT.

It expects an input of shape $(B, F, T)$ and extends it along the frequency axis using the complex conjugate to form a tensor of shape $(B, n_{\text{fft}}, T)$. The SSM produces an output of identical shape, but the represented information is transformed into the time domain via a C-matrix initialized with inverse Fourier transform (IFT) coefficients. Each column (corresponding to a frame in the original spectrogram) is scaled by a user-specified window $\mathcal{W}$, and the signal is reconstructed as:

$$y(n) = \frac{\sum_{m=-\infty}^{\infty} \mathcal{F}^{-1}\{\hat{X}(m\cdot n_{\text{hop}}, \cdot)\}(n) \mathcal W(n - m \cdot n_{\text{hop}})}{\mathbf s_{\text{OLA}}(\mathcal W)(n)}$$

where $\mathbf s_{\text{OLA}}$ is the sum of overlapping squared windows.

## Training & Evaluation scripts

The pipeline provides single-GPU and multi-GPU (Distributed Data Parallel) scripts for training individual components or end-to-end models, as well as evaluation scripts.

| Script | Mode | Target Module | Description |
| :--- | :--- | :--- | :--- |
| `train.py` | Single-GPU | OpenUnmix Backbone | Standard single-GPU training script for original OpenUnmix models. |
| `train_parallel.py` | Multi-GPU (DDP) | OpenUnmix Backbone | Multi-GPU Distributed Data Parallel training script for OpenUnmix models. |
| `train_spectrogram.py` | Single-GPU | `Trainable_spectrogram` | Single-GPU training script for the C-MagSSM spectrogram encoder. |
| `train_spectrogram_parallel.py` | Multi-GPU (DDP) | `Trainable_spectrogram` | Multi-GPU DDP training script for `Trainable_spectrogram` with window regularization ($\alpha$). |
| `train_decoder.py` | Single-GPU | `Trainable_decoder` | Single-GPU training script for the C-MagSSM decoder module. |
| `train_decoder_parallel.py` | Multi-GPU (DDP) | `Trainable_decoder` | Multi-GPU DDP training script for the `Trainable_decoder` module. |
| `train_magssm_parallel.py` | Multi-GPU (DDP) | End-to-End MagSSM UMX | Joint end-to-end multi-GPU DDP training script for the complete MagSSM UMX pipeline. |
| `evaluate.py` | Single-GPU | Full Pipeline | Single-GPU evaluation script computing SDR, SIR, SAR, and ISR metrics on MUSDB18 test set. |
| `evaluate_parallel.py` | Multi-Process | Full Pipeline | Parallelized evaluation script running metrics evaluation concurrently across test tracks. |


## Models & Architecture Wrappers

- `magssm_umx.py`: Integrated model class wrapping `Trainable_spectrogram` with OpenUnmix separation backbone.
- `sedge_umx.py`: Integrated model class combining SEdge SSM layers with OpenUnmix architecture.


## Utilities & Helpers

- `utils_edge_var.py`: Core utility module providing SSM matrix discretizations, S4/SEdge structured initializations, and stability enforcement methods.
- `utils_spectrogram.py`: Helper functions to initialize, configure, and load `Trainable_spectrogram` model checkpoints.
- `utils_decoder.py`: Helper functions to initialize and load `Trainable_decoder` checkpoints.
- `downsample_musdb18.py`: Audio preprocessing utility to downsample MUSDB18 dataset tracks (e.g., to 14.7 kHz) for reduced memory consumption.
- `path_config.py`: Environment configuration script adding relative module paths (`SEdge`, `openunmix`) dynamically to `sys.path`.
- `data_bis.py`: Variant of `data.py` with reduced validation chunk durations to fit GPU memory constraints.
- `cli.py`: Command-line interface for applying trained separation models directly to audio files.
